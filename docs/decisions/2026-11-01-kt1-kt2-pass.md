# KT1 and KT2 pass: NEAR AI signatures verify on-chain, no relayer

2026-11-01 · Decided by Furqaan · Status: accepted

## Context

The [kill-test record](./2026-11-01-build-intented-with-sealed-lite-fallback.md) made Intented depend on KT1 (a real signed verdict that recovers locally) and KT2 (the same verified in a testnet contract). If KT2 failed, a relayer with its own key would verify off-chain.

## Decision

**KT1 passes** (`firewall-core/scripts/kt1.ts`). The attestation report, fetched with a fresh nonce before the completion, echoes the nonce. One non-streaming completion returns a `provider_tee` signature over `{model_id}:{sha256(request)}:{sha256(response)}` whose EIP-191 signer is the attested signing address. Both models pass:

| Model | Signing address | Latency | Response |
| --- | --- | --- | --- |
| `Qwen/Qwen3.8-27B`, thinking on | `0x835ab53d20294ef795906dff21ae4c045336aa26` | 50.1 s | 8,599 B |
| `Qwen/Qwen3.8-27B`, thinking off | same | 3.6 s | 811 B |
| `z-ai/glm-5.3-flash`, thinking off | `0x3b753b4406613c5e70ae640508632b600424fa0c` | 1.5 s | 719 B |

KT1 checks the nonce and the signer only. It does not verify the TDX quote or the NVIDIA evidence.

**KT2 passes** (`contract/kt2-verify`, deployed at `kt2.intented-owner.testnet`). `verify(req, resp, sig)` rebuilds the signed text, applies EIP-191, recovers with `env::ecrecover` and checks an allowlist. On testnet, with the real Qwen pairs:

| Call | Result | Gas burnt | Transaction |
| --- | --- | --- | --- |
| 811 B response | `true` | 2.45 Tgas | `5EPABmC3cRqWVm4oxTu2RN6Dj9xfhJbEE5NhkpWwoB1B` |
| same, one byte flipped | `false` | | `DezXFnG7CxPydbNDMNN2JzD8WpJxc1zqnSYGv6j5HbxQ` |
| 8,599 B response | `true` | 3.72 Tgas | `J1MRhZurzsbBsPciNgQKEvyBTRnNRY53bKyrH2GsMrKi` |
| same, one byte flipped | `false` | | `EfJNqXUhoisg4eqvK2mxnq8BnqiJroEMQordyMocaaZ7` |

A function-call key on `intented-agent.testnet`, scoped to `verify` on the KT2 contract, succeeds in scope (`bWiYnw2eiAKuvJSXxC6mQSHuVPeFw84sSEeW5gifvD4`). The network rejects it for `register_signer` on the same contract (`MethodNameMismatch`) and for any call to `wrap.testnet` (`ReceiverMismatch`). Rejected transactions have no hash.

So:

- **No relayer.** The contract verifies NEAR AI's signature itself, through `env::ecrecover` (near-sdk's `unstable` feature exposes it).
- **The firewall core always sends `chat_template_kwargs: {enable_thinking: false}`.** With thinking on, latency and response size miss KT3's 5 s bar and the 4 KB budget.
- **The prompt carries a trusted token table** (`firewall-core/src/tokens.ts`): contract, symbol and decimals as `ft_metadata` reported on 2026-11-01. Without it the model cannot tell real USDC from a look-alike and denies honest payments; with it, a transfer on any other token contract is denied.
- **The verdict schema puts `reason` before `verdict`.** Generated verdict-first, the model committed to `DENY` before reasoning and then argued against itself in the reason.

## Consequences

- The signed text carries the model id, which the interface spec does not. Proposed in [the signed-text record](./2026-11-01-signed-text-includes-model-id.md); needs William.
- Each model has its own signing address, so switching model means re-registering the signer.
- Early KT3 smoke test (three cases, three runs each): both models 9/9 correct; median latency 4.88 s on Qwen, about 1.9 s on GLM. KT3 proper is William's 20 + 20 cases.
- Testnet accounts `intented-owner`, `intented-agent` and `intented-attacker` exist; their keys belong in the shared password manager.
